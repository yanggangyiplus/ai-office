# AI 오피스 v2: 내 공간과 걸어 다니는 팀 공간 설계

v1 설계(`2026-11-17-ai-office-design.md`)를 바탕으로 한다. v1의 회의록 정리, 확정, GitHub 이슈, 현황판 기능은 그대로 쓰고, 그 위에 "공간"을 얹는다. 이 문서는 ①내 공간·개인 연결·팀 보드와 ②팀 공간(걷기·채팅)을 다룬다. ③내 일정은 이 문서의 범위가 아니며 별도 설계로 뒤에 한다.

## 의도와 이유

v1은 정보는 있지만 "오피스" 느낌이 없다. 로그인하면 내 공간이 있고, 팀을 골라 입장하면 같은 팀원이 캐릭터로 걸어 다니는 ZEP 같은 공간에서 현황을 같이 보고, 말을 걸고, 채팅하고 싶다. 말로 묻지 않아도 서로의 작업이 보인다는 v1의 목적은 같다.

## 목표 / 비목표 / 반목표

**목표**
- 로그인하면 **내 공간**(걸어 다닐 수 있는 작은 방)이 나온다.
- 내 공간에서 **GitHub와 Notion을 내 계정으로 연결**하고 연결 상태를 본다.
- 내 공간에 **팀 보드**(내가 속한 팀 목록)가 있고, 팀을 골라 **입장하기**를 누르면 팀 공간으로 간다.
- **팀 공간**은 팀원 모두의 캐릭터가 같은 맵에서 **실시간으로 걷는** 곳이다.
- 팀 공간에서 **채팅**(말풍선과 채팅창)을 할 수 있다. 기록은 저장되어 다시 입장해도 최근 대화가 보인다.
- v1의 회의 목록, 회의 확정, 이슈 생성, 팀원별 현황판이 맵 안의 구역으로 들어간다.

**비목표 (이번 범위 밖)**
- 내 일정(③), 음성·화상 통화, 가까이 가면 들리는 근접 채팅, 아바타 꾸미기, 맵 편집기, 모바일 터치 조작
- GitHub·Notion OAuth 로그인 방식의 연결(이번에는 토큰 붙여넣기, 아래 참고)

**반목표**
- 팀원이 아닌 사람에게 위치나 채팅이 전달되는 것
- 개인 토큰을 평문으로 저장하거나 화면·브라우저에 다시 보내는 것
- 걷기가 끊겨서 "뚝뚝 순간이동"으로 보이는 것

## 접근 방식 (고른 것과 이유)

실시간을 어디에 맡길지 세 가지를 비교했다.
- **A. 실시간 전용 서비스 (선택)**: Vercel에서 웹소켓 서버를 못 돌리고, 직접 운영 부담이 없다.
- B. 별도 웹소켓 서버 배포: 자유롭지만 서버를 하나 더 운영해야 한다.
- C. 폴링: 걷는 느낌이 안 나서 제외.

사용자가 A, 추천대로 진행하기로 했다.

## 내가 정한 것 (사용자가 합의한 것이 아님)

- **실시간 서비스는 Ably.** Auth.js 로그인과 맞추기 쉽다. 서버가 요청한 사람이 속한 팀의 채널만 쓸 수 있는 **짧은 수명의 토큰**을 발급한다(`/api/realtime/token`). 채널 이름은 `team:<팀id>`. Supabase Realtime은 자체 인증(JWT)에 묶여 있어 Auth.js와 맞물리기 번거로워서 제외했다.
- **위치는 클라이언트가 직접 발행**(초당 약 10회, 방향·좌표). 받는 쪽은 부드럽게 보간해서 그린다. 위치를 속이는 것(다른 사람 위치를 거짓으로 보내기)은 막지 않는다. 팀 안에서만 보이고 위험이 낮아서.
- **채팅은 서버를 거친다.** 클라이언트가 `POST /api/teams/<id>/chat`로 보내면 서버가 멤버인지 확인하고 DB(Neon)에 저장한 뒤 Ably로 발행한다. 입장할 때 최근 100개를 불러온다. 메시지 길이는 500자까지.
- **Ably 키가 없는 개발 환경**에서는 같은 브라우저의 다른 탭끼리만 통하는 로컬 대체 방식(BroadcastChannel)을 쓴다. 키 없이도 탭 두 개로 걷기·채팅을 시험할 수 있게 하려고. 운영에서는 키가 없으면 팀 공간 입장을 막고 안내한다.
- **개인 연결은 토큰 붙여넣기.** 내 공간의 컴퓨터를 누르면 GitHub 개인 액세스 토큰과 Notion 연동 토큰을 각각 붙여넣는 창이 열리고, 만드는 방법을 화면에서 안내한다. 사람마다 DB에 암호화해서 저장하고 다시 보여주지 않으며 "연결됨"만 표시한다. OAuth("GitHub로 연결" 버튼)는 서비스마다 앱 등록이 필요해서 뒤로 미룬다. 이 선택은 "연결 경험이 덜 매끄럽다"는 비용이 있다.
- **v1의 팀 단위 토큰은 개인 토큰으로 바뀐다.** 이슈 만들기는 누르는 사람의 GitHub 토큰으로, 회의록 읽기는 올리는 사람의 Notion 토큰으로 한다. 현황판은 보고 있는 사람의 GitHub 토큰으로 읽는다. 토큰이 없으면 해당 구역에 "먼저 내 공간에서 연결하세요"를 보여준다. 팀 단위로 남는 설정은 관리자가 정하는 **저장소 목록과 Notion '회의록' 상위 페이지**뿐이다.
- **용어**: 화면에서는 "오피스"를 "팀"이라고 부른다. DB 테이블 이름(`offices`)은 그대로 둔다.
- **맵**: 고정된 타일 맵 하나(팀 공간)와 작은 방 하나(내 공간)를 데이터로 정의하고 2D 캔버스에 그린다. 방향키/WASD로 걷고 벽·책상에는 부딪힌다. 별도 게임 라이브러리는 쓰지 않는다. 아바타는 v1의 8×8 캐릭터를 방향에 맞춰 그린다.
- **팀 공간 구역**: 회의실(들어가면 회의 목록과 회의록 올리기 패널), 현황판 벽(가까이서 상호작용하면 팀원별 하는 중/다음/끝남), 각자의 책상(팀원 수만큼, 입장 순서가 아니라 멤버 목록 순서로 고정 배정). 상호작용은 구역에 서서 E키 또는 클릭.
- **내 공간 오브젝트**: 컴퓨터(연결 설정), 팀 보드(팀 목록, 입장하기, 새 팀 만들기, 초대 링크로 입장), 문(로그아웃).
- **접속 표시**: 팀 공간에 들어와 있는 사람만 맵에 나타난다. 접속하지 않은 팀원은 책상이 비어 있고 현황판에는 그대로 나온다.
- **테스트 로그인과 개발용 메모리 DB는 그대로 유지**한다(v1 설계 이후 추가분).

## 핵심 흐름

1. 로그인 → 내 공간 도착
2. 컴퓨터에서 GitHub·Notion 토큰 연결(선택, 나중에 해도 됨)
3. 팀 보드에서 팀 선택 → 입장하기 → 팀 공간 도착(내 책상 옆)
4. 맵을 걸어 다니며 팀원을 보고, 구역에서 회의·현황판 기능을 쓰고, 채팅
5. 나가기(내 공간으로) 또는 창을 닫으면 맵에서 사라진다

## 검토 후 추가로 정한 것 (내 판단, 사용자 확인 필요)

- **기존 팀 토큰 컬럼은 삭제한다.** `offices.notionToken`, `offices.githubToken`을 지우고 사람별 연결 테이블로 옮긴다. 아직 배포한 적이 없고 실제 데이터가 없어서 파괴적 마이그레이션이어도 잃는 것이 없다. 기존 v1 흐름은 개인 토큰으로 바뀌어 계속 동작한다.
- **Notion 접근 조건**: 회의록을 올리는 사람의 Notion 연동이 관리자의 '회의록' 상위 페이지에 공유되어 있어야 한다. 아니면 기존 `not_found` 오류가 나고, 화면은 "이 페이지가 내 Notion 연동에 공유되어 있지 않습니다"라고 알려 준다. 이것은 팀이 받아들이는 요구사항이다.
- **이슈 만들기는 누르는 사람 기준.** 그 사람이 대상 저장소에 이슈를 만들 권한이 없으면 대체 없이 실패하고 GitHub의 이유를 쉬운 말로 보여 준다(기존의 선점·해제 로직이 반쯤 만들어진 이슈를 막는다). 담당자는 `githubUsername`으로 지정하고, GitHub가 협업자가 아니라고 무시하면 담당자 없이 만들어진다.
- **실시간 구분과 테스트**: `ABLY_API_KEY`가 없고 `NODE_ENV`가 production이 아니면 로컬 대체 방식, production인데 키가 없으면 입장을 막고 안내한다. 실시간 코드는 "전송 계층" 인터페이스(보내기, 받기, 접속 목록) 하나를 두고 Ably 구현과 로컬(BroadcastChannel) 구현이 같은 인터페이스를 따른다. 테스트는 메모리 안의 가짜 구현으로 한다.
- **위치 발행 빈도**: 움직이는 동안에만 초당 약 5회(앞에서 말한 10회에서 낮춤)로 보내고, 받는 쪽이 보간한다. Ably 무료 한도를 아끼려고.
- **접속 단위**: 운영에서는 **사용자당 캐릭터 하나**. 같은 사람이 탭을 하나 더 열면 새 탭이 이기고 먼저 열린 탭은 "다른 곳에서 접속했습니다"를 보여 주고 연결을 끊는다. 로컬 대체 방식에서는 탭마다 캐릭터 하나(같은 이름이 두 개 보여도 된다). 탭 두 개로 시험하려는 용도라서.
- **늦게 들어온 사람이 현재 위치를 보는 법**: Ably의 접속 목록(presence) 데이터에 마지막 좌표를 싣고, 움직임이 멈출 때와 움직이는 동안 5초마다 갱신한다. 로컬 대체 방식은 입장할 때 인사를 보내고 다른 탭이 현재 좌표로 답한다.
- **책상 배정**: `members`에 `joinedAt`(가입 시각)을 추가하고 `joinedAt`, `userId` 순으로 책상을 준다. 새 멤버는 다음 빈 책상을 받고, 멤버가 나가면 뒤 사람들이 한 칸씩 당겨진다(조용히 바뀌는 것을 받아들인다). 책상은 **최대 12개**이고, 13번째 이후 멤버는 책상 없이 입구에서 시작한다.
- **기존 화면은 모두 없애지 않는다.** `/offices`(목록)는 내 공간으로 리디렉션하고, `/offices/[id]` 등 기존 팀·회의·설정 화면은 **"목록으로 보기"로 남긴다**(이미 만들어져 있어 비용이 거의 없다). 캔버스 맵은 키보드·화면 낭독기로 쓰기 어려워서, 맵의 모든 기능(회의, 현황판, 채팅)을 HTML 패널로도 열 수 있게 하고 이 목록 화면을 접근 가능한 대안으로 둔다.

## 빌더에게 남기는 것

- 맵 크기와 타일 그림, 구역의 정확한 위치, 책상 배치(최대 인원 포함)
- 걷기 속도, 보간 방식, 위치 발행 주기의 세부 조정
- 토큰 연결 창의 안내 문구, 오류 문구
- 채팅 말풍선이 사라지는 시간, 채팅창의 스크롤 처리
- 현재 `offices` 관련 화면(`/offices/[id]` 등)을 새 공간 화면으로 옮기는 순서와 URL 구조
