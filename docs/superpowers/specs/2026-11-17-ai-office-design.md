# AI 오피스 설계 (v1)

## 의도와 이유

팀 프로젝트용 웹사이트. 팀원이 한 "오피스"에 모여, 묻지 않아도 팀 현황이 보이게 한다.

해결할 문제 두 가지:
1. 회의 내용이 각자에게 흩어져 있고 정리된 적이 없다.
2. 팀원별 작업량·순서·진행도를 계속 물어봐야 안다.

이 도구는 흩어진 기록을 모으는 도구가 아니라, "회의 후 Notion에 쓰고 링크를 올린다"는 **팀의 규칙을 만드는 도구**다.

## 목표 / 비목표 / 반(反)목표

**목표 (v1)**
- 구글 로그인 후 팀 오피스에 입장, 팀원 초대
- Notion 회의록 링크를 올리면 AI가 결정 사항·할 일·담당자로 정리해 보여준다
- 정리 결과를 팀원이 확인하면 확정되고, 확정된 할 일은 GitHub 이슈로 만들 수 있다
- GitHub 이슈·PR을 읽어 팀원별 "하는 중 / 다음 / 끝남" 현황판을 보여준다

**비목표 (v1 이후로 미룸)**
- 출퇴근, 브레인스토밍, 기획서·체크리스트 생성, PR 알림
- 사이트 안에서 회의록 직접 작성, 회의 전사

**반목표 (이러면 기능이 돌아가도 실패)**
- 커밋 수·코드 줄 수로 팀원을 비교하는 화면 (진행 상태 중심으로 보여준다)
- AI가 정리한 담당자·할 일을 확인 없이 확정하거나 이슈로 만드는 것

## 제약

- 팀 프로젝트 규모(소수 인원)를 가정한다. 인원수와 저장소 개수는 미확인.
- 회의록은 아직 존재하지 않는다. 팀이 Notion에 쓰는 습관부터 만들어야 한다.

## 접근 방식 (고른 것과 이유)

회의 내용이 들어오는 방식 세 가지를 비교했다.
- A. 사이트에 텍스트 붙여넣기: 가장 단순하지만 사람이 한 번 더 옮겨야 한다.
- **B. Notion 링크 공유 (선택)**: 기존에 쓰는 도구를 유지한다. 단점은 Notion에 쓰는 습관과 연동 설정이 필요하다는 점.
- C. 사이트 안 작성: 가장 크므로 v1에 맞지 않는다.

사용자가 B를 선택했다.

## 내가 정한 것 (사용자가 합의한 것이 아님)

- **스택**: Next.js를 Vercel에 배포. 구글 로그인은 Auth.js(구글 제공자). 저장소는 관리형 Postgres 하나.
- **Notion 연동**: 팀당 Notion 내부 연동(integration) 하나. 팀이 "회의록" 상위 페이지를 만들고 연동을 한 번 연결하면, 그 아래 페이지는 모두 읽힌다. 팀원별 OAuth는 설정이 무거워 v1에서 제외. 링크가 그 상위 페이지 밖이면 거부하고 이유를 안내한다.
- **GitHub 연동**: 오피스당 저장소 목록과 읽기·이슈 생성 권한의 토큰 하나. 팀원별 로그인 연동은 v1에서 제외.
- **AI**: Claude API로 회의록을 구조화(결정/할 일/담당자) 출력. 담당자는 오피스 팀원 목록에 있는 이름·GitHub 계정과만 매칭하고, 매칭 안 되면 "담당자 미정"으로 둔다.
- **현황 갱신**: 실시간이 아니라 페이지를 열 때 + 수동 새로고침으로 GitHub를 읽는다.

## 핵심 흐름

1. 구글 로그인 → 오피스 만들기 또는 초대 링크로 입장
2. 회의 후 팀원이 Notion 링크 등록 → AI 정리(초안)
3. 팀원이 초안을 고치고 확정 → 확정된 할 일 중 선택해 GitHub 이슈 생성
4. 현황판에서 팀원별 이슈·PR 상태 확인

## 검토 후 추가로 정한 것 (내 판단, 사용자 확인 필요)

- **오피스 규모**: 여러 오피스를 만들 수 있는 구조(오피스별 데이터 분리). 토큰은 오피스별로 DB에 암호화해 저장한다.
- **권한**: 오피스를 만든 사람이 관리자. Notion 상위 페이지·GitHub 토큰·저장소 목록 설정과 멤버 제거는 관리자만. 나머지는 일반 멤버. 토큰은 화면에 다시 보여주지 않는다.
- **GitHub 계정 매핑**: 멤버가 입장할 때 본인 GitHub 사용자명을 직접 입력한다. 이 값으로 담당자 매칭과 현황판 그룹핑을 한다.
- **회의 상태**: 초안 → 확정 → (이슈 생성). 확정은 업로더 포함 어떤 멤버든 할 수 있다. 확정된 내용은 그 시점의 스냅샷이고 Notion 변경은 따라가지 않는다. 확정 전에는 AI 재정리와 수정이 가능, 확정 후에는 수정만 가능.
- **할 일 필드**: 제목, 담당자, 대상 저장소, 설명(선택). 마감일·우선순위는 v1에서 제외. 대상 저장소는 오피스 기본값을 쓰고 할 일마다 바꿀 수 있다.
- **"다음" 분류**: 규칙으로 계산한다(나에게 할당됨 + 열려 있음 + 연결된 PR 없음). 라벨·마일스톤 규칙은 요구하지 않는다.
- **긴 회의록**: Notion 본문을 텍스트로만 추출하고(데이터베이스·임베드는 무시), 길이 상한을 넘으면 오류로 알려준다. 한국어 입력을 기본으로 가정.
- **DB 제공자**: Neon(Postgres)으로 가정. 비용 상한은 정해진 것 없음.

## 빌더에게 남기는 것

- 데이터 모델 세부(오피스, 멤버, 회의, 할 일), 화면 레이아웃, 에러 문구
- 토큰 보관 방식(서버 환경변수 vs DB 암호화)
- 현황판의 정확한 상태 분류 기준(이슈 라벨, PR 상태를 어떻게 "하는 중"으로 볼지)
