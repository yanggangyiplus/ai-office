# AI 오피스 v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 구글 로그인 → 오피스 → Notion 회의록 AI 정리·확정 → GitHub 이슈 생성 → 팀원별 현황판까지 동작하는 웹사이트.

**Architecture:** Next.js(App Router) 한 앱. 외부 연동(Notion, GitHub, Claude)은 `src/lib/` 아래 순수 함수 모듈로 두고 HTTP 클라이언트를 인자로 주입해 테스트한다. DB는 Neon Postgres + Drizzle. 페이지는 서버 컴포넌트에서 lib를 직접 호출한다.

**Tech Stack:** Next.js, TypeScript, Auth.js(Google), Drizzle ORM + Neon, `@anthropic-ai/sdk`, `@notionhq/client`, `@octokit/rest`, Vitest, Vercel 배포.

**Spec:** `docs/superpowers/specs/2026-11-17-ai-office-design.md`

## Global Constraints

- 구글 로그인은 Auth.js 구글 제공자만 사용한다.
- Notion 연동은 오피스당 내부 연동(integration) 토큰 하나. 링크가 관리자가 지정한 "회의록" 상위 페이지 하위가 아니면 거부한다.
- GitHub 연동은 오피스당 토큰 하나와 저장소 목록. 팀원별 GitHub 로그인 없음.
- 토큰은 오피스별로 DB에 암호화 저장하고 화면에 다시 보여주지 않는다.
- AI 정리 결과는 사람의 확정 없이 확정·이슈 생성되지 않는다.
- 담당자는 오피스 멤버의 이름·GitHub 사용자명과만 매칭하고, 안 맞으면 "담당자 미정"(null).
- 할 일 필드: 제목, 담당자, 대상 저장소, 설명(선택). 마감일·우선순위 없음.
- 회의 상태: `draft` → `confirmed`. 확정 후에는 AI 재정리 불가, 수정만 가능. 확정 내용은 스냅샷.
- 현황판은 이슈·PR 상태 중심. 커밋 수·코드 줄 수 비교 화면 금지.
- "다음" = 나에게 할당됨 + 열려 있음 + 연결된 PR 없음. "하는 중" = 할당됨 + 열려 있고 연결된 열린 PR 있음. "끝남" = 닫힘.
- 출퇴근, 브레인스토밍, 기획서 생성, PR 알림은 만들지 않는다.
- 회의록 본문은 텍스트만 추출하고 길이 상한(30,000자) 초과 시 오류. 한국어 기본.
- AI 모델 ID: `claude-sonnet-5-5`.

## Review Focus

1. Notion 링크가 상위 페이지 밖이거나 접근 불가일 때: 이유를 알려주는 오류, 초안을 만들지 않음.
2. AI가 존재하지 않는 담당자 이름을 내놓을 때: 담당자 null로 저장.
3. 초대 링크를 이미 멤버인 사용자가 다시 열 때: 중복 멤버 생성 없이 오피스로 이동.
4. 관리자가 아닌 멤버가 토큰 설정 API를 호출할 때: 403.
5. 이미 확정된 회의를 다시 확정·재정리 요청할 때: 거부, 이슈 중복 생성 없음.
